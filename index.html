Section 01

Why Version Control
Matters

Git is the world's most popular distributed version control system. It tracks changes, enables collaboration, and lets you travel back in time through your code's history.

🕰️

Time Travel

Revert any file — or your entire project — to a previous state. Made a catastrophic mistake? Roll back instantly.

🌿

Parallel Branches

Work on multiple features simultaneously. Branches isolate changes so experiments never break your main codebase.

👥

Team Collaboration

Multiple developers can work on the same project without overwriting each other's work. Merge intelligently.

📝

Full Audit Trail

Every change is logged with who made it, when, and why. Code review, accountability, and blame — all built in.

⚡

Blazing Fast

Git is local-first. Most operations happen offline at lightning speed. Only push/pull when you need the network.

🔒

Data Integrity

Every file, commit, and tree is checksummed with SHA-1. Corruption or tampering is instantly detectable.

Section 02

Git vs GitHub
They're not the same thing

A common confusion — Git is the tool, GitHub is the platform. Here's the real difference:

Git

The Version Control System

  • Installed locally on your machine
  • Tracks changes in your files
  • Created by Linus Torvalds in 2005
  • Works completely offline
  • Command-line tool at its core
  • Free and open-source (GPL v2)
  • No account or sign-up required
GitHub

The Cloud Platform

  • Web-based hosting for Git repos
  • Adds PRs, Issues, Actions & more
  • Acquired by Microsoft in 2018
  • Requires internet connection
  • GUI + API + CLI available
  • Free tier + paid plans (Copilot, Teams)
  • 100M+ developers worldwide
Section 03

Essential Commands

Click any command to copy it. Master these and you'll handle 95% of real-world Git workflows.

git initBASIC
Initialize a new Git repository in the current directory. Creates a hidden .git folder to start tracking.
git clone <url>BASIC
Clone (download) an existing repository from a URL to your local machine with full history.
git statusBASIC
Show the state of your working directory and staging area. See tracked, untracked, and modified files.
git add .BASIC
Stage ALL modified and new files in the current directory for the next commit.
git add <file>BASIC
Stage a specific file for commit. Use this for selective staging of only certain changes.
git commit -m "msg"BASIC
Commit staged changes with a descriptive message. Each commit is a permanent snapshot in history.
git log --onelineBASIC
Display a compact commit history. One commit per line with hash and message — easy to scan.
git diffBASIC
Show line-by-line differences between your working directory and the last commit. See exactly what changed.
git rm <file>BASIC
Remove a file from both the working directory and from Git tracking. Stage the deletion for commit.
git branchBRANCH
List all local branches. The current branch is highlighted with an asterisk (*) symbol.
git branch <name>BRANCH
Create a new branch with the given name. Does NOT switch to it — it stays on the current branch.
git checkout -b <name>BRANCH
Create AND switch to a new branch in one command. The go-to shortcut for starting new features.
git switch <branch>BRANCH
Switch to an existing branch. The newer, cleaner alternative to git checkout for branch switching.
git merge <branch>BRANCH
Merge the specified branch into your current branch. Combines commit histories and creates a merge commit.
git branch -d <name>BRANCH
Delete a branch (only if it's been fully merged). Use -D to force-delete even if unmerged.
git stashBRANCH
Temporarily shelve your current uncommitted changes so you can switch branches without losing work.
git stash popBRANCH
Restore the most recently stashed changes back to your working directory and remove from stash list.
git remote add origin <url>REMOTE
Connect your local repo to a remote repository (usually on GitHub). "origin" is the conventional name.
git push origin mainREMOTE
Upload your local main branch commits to the remote repository on GitHub.
git pullREMOTE
Fetch changes from the remote and immediately merge them into your current branch. = fetch + merge.
git fetchREMOTE
Download remote changes WITHOUT merging them. Lets you inspect before integrating.
git remote -vREMOTE
List all configured remote connections with their URLs (fetch and push). Verify your remote setup.
git push -u origin <branch>REMOTE
Push a branch and set upstream tracking. After this, just git push works for this branch.
git push --force-with-leaseREMOTE
Safer force push. Rejects if others pushed since your last fetch — prevents overwriting team's work.
git rebase mainADVANCED
Reapply your commits on top of main. Creates a cleaner linear history compared to merging.
git rebase -i HEAD~3ADVANCED
Interactive rebase: squash, reorder, or edit the last 3 commits before pushing. Powerful history rewriting.
git cherry-pick <hash>ADVANCED
Apply a specific commit from another branch onto your current branch. Pick only what you need.
git reset --soft HEAD~1ADVANCED
Undo the last commit but keep all changes staged. Perfect for fixing a premature commit.
git reset --hard HEAD~1ADVANCED
Undo the last commit AND discard all changes. ⚠️ Destructive — data is gone. Use with caution.
git bisect startADVANCED
Start binary search through commit history to find which commit introduced a bug. Incredibly powerful.
git tag v1.0.0ADVANCED
Create a lightweight tag at the current commit. Use annotated tags (-a) for releases with metadata.
git reflogADVANCED
Show a log of all reference changes. A lifesaver for recovering "lost" commits after hard resets.
gh repo createGH CLI
Create a new GitHub repository from the terminal. Interactive prompts for name, visibility, and more.
gh pr createGH CLI
Open a Pull Request on GitHub directly from your terminal. Add title, body, reviewers, and labels.
gh pr listGH CLI
List all open Pull Requests in the current repository. Filter by author, label, or assignee.
gh issue createGH CLI
Create a new GitHub Issue with a title, body, and labels — without leaving the terminal.
gh repo clone <user/repo>GH CLI
Clone a GitHub repo using its shorthand "username/repo" format. Automatically sets up remote tracking.
gh auth loginGH CLI
Authenticate the GitHub CLI with your account. Supports browser-based OAuth or token-based login.
Section 04

The Git Workflow
Feature Branch Flow

The industry-standard workflow used by millions of teams. Follow these steps for every feature or bug fix.

01

Create a Feature Branch

Never commit directly to main. Create an isolated branch: git checkout -b feat/user-auth. This keeps main always deployable.

02

Make Changes & Commit Often

Write code, then stage and commit frequently: git add . → git commit -m "feat: add JWT validation". Small commits = easier reviews.

03

Push to GitHub

Upload your branch: git push -u origin feat/user-auth. This backs up your work and makes it visible to teammates.

04

Open a Pull Request

On GitHub, open a PR from your branch to main. Add description, screenshots, and request reviewers. This triggers CI/CD checks.

05

Code Review & Iteration

Teammates leave comments. You respond with new commits. Push again — the PR updates automatically. Collaborate until it's approved.

06

Merge & Clean Up

Merge the PR into main. Delete the feature branch on GitHub. Locally: git checkout main → git pull → git branch -d feat/user-auth.
